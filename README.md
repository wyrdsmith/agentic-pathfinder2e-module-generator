# Instant Pathfinder (Working Name)
This will house the development of the Pathfinder 2e Module Generator.

## The Goal
To create and develop an adventure module generator for Pathfinder 2e.

### What is an Adventure Module?
An adventure module consists of a quest, which is a story with three acts. Each act has a number of scenes, and 
each scene has an encounter. The adventure module also includes a number of NPCs and locations, as well as treasure.
These are all generated by the system. A module should be balanced for a party of 4 level 1 characters (number of 
characters and level will be adjustable) and the sum of all encounters should have an experience total of 1000 or more which is the amount needed to gain a single level.

#### Why does every scene have an encounter, and why only one?
LLMs are dumb. They are not capable of reliably creating the logic chains required to produce multiple encounters per scene let alone how to write a scene that's purely for character interaction. The easiest way I could approach the problem of roleplay scenes was to treat them as social encounters where the players attempt to influence one or more NPCs. This way the adventure module will still feel like a published adventure as it's played. And limiting the number of encounters to one per scene keeps things simple for an otherwise incredibly complex task.

### Why an LLM-Based Generator?
Gamemasters have always had access to random tables for generating game content. These days there are a plethora of random generators for encounters, loot, npcs, etcetera, that can be found online. The purpose of this tool is not to replace the GM or those other tools, but to provide a tool that can generate balanced, ready-to-play, adventure modules in an effort to get people playing at the table faster.

Using an LLM is essentially like using a fancy random number generator, but instead of integers it spits out strings of words that, fingers crossed, are coherent enough to tell a story. And that's really all this tool is going to be, a fancy random number generator that slowly strings together a bunch of other fancy number generators and outputs something that resembles an adventure module.

#### LLM Models Used
I'm currently testing using Gemma4:12b for creativity and reasoning and Qwen2.5:7b for data extraction. I might try testing other models once I've finished initial development, but that's not likely to happen for a while. Note, I did create custom agents using model files to increase the token limit to 16384.

## Who should use this tool?
No one. No one should use this tool. It takes all the imagination and creativity out of creating a Pathfinder 2e adventure. If you're a new GM, go read a book. Read a module. Read a adventure path. Learn how they work. Actually put some thought into what you're doing. This tool does not help you become a better GM. If anything, it teaches you to be a lazy, uncreative GM.

If you're an experienced GM, you're better than this tool. You don't need this tool. You can make your own adventures. You can make better adventures than this tool. Don't use this tool.

### So who is this tool for?
I don't know. Maybe someone will enjoy the novelty, or some GM is dealing with burnout, but still wants to keep playing with their friends. Maybe someone calls out sick and the group still wants to play and they don't have $5 to drop on a well-written adventure created by experts on DriveThruRPG, but they do have a decent computer with at least 32GB of RAM and they're willing to spend a few hours generating the adventure.

This tool is not intended to replace homebrew content, nor is it a replacement for published adventure modules that have gone through rigorous review and testing by some of the most creative minds out there. It's going to have balancing, continuity and logic issues. What will be produced by this tool will in no way be a finished product. My best hope for this project is that it will help people better learn and understand Pathfinder 2e and gamemastering while providing another asset in a GM's toolkit for having fun with their friends.

### Can I sell modules generated by this tool?
Don't. Just... don't. Ok? You're better than that. Be better.

## Current Progress
I've begun actual work on the module generator. As of this moment, the generator is capable of producing a three-act quest with 4-9 scenes per act, an overall summary of the quest, a unique title for the quest and the theme for the quest. Each scene provides a summary of the events in the scene, the location of the scene, the encounter type intended for that scene as well as whether or not the scene offers a rest opportunity after the encounter.

I'm using a multi-agent approach to the module generation with Gemma4:12b being used for the creative writing and Qwen2.5 being used for extracting the data from the creative writing and formatting it into pydantic objects. I've set up dependency injection to allow agents to be more aware of the quest data, depending on the tools provided to the agent.

I also updated the plot_hooks table to quest_concepts to include all the data about the quest idea so that agents are less likely to repeat settings, npcs, and other quest details.

I've layed the foundation for npc generation by creating a Markov Chain name generator using a database of ancestry appropriate seed names. I'll need to also create a name generator for `[adjective] + [noun]` names and Surki names which are epithets. Right now, for those specific ancestries with more structured names, I'm just randomly selecting one from the list of names in the database.

Threat level adjustment, encounter experience balancing/budgeting and reward budget distribution has all now been set up. During generation I'm consistently getting well above 1000xp across all encounters, and after some slight tweaking, I'm getting around 1100 to 1200xp per quest. While high, if I tweak the number of scenes produced to reduce encounter count to get almost exactly 1000xp, the quest winds up having two or more extreme encounters, often back to back in the third act. As it is now, there's usually, at most, one extreme encounter, with several severe encounters. It's a trade off I'm willing to make. 

I've also built out the NPC Generation Tools and Agents and have successfully generated a global list of key NPCs that appear in the quest. Next I'll focus on finalizing NPC generation by adding the NPC details such as description, behavior, attitude, etc. 

The next step is encounter design and generation. I've already set up some of the tools and agents for this. Each encounter type has its own agent with specific system instructions and tools. Combat and Hazard encounters are easy, Social encounters should be relatively easy once NPC details are fleshed out. The tricky one is Skill Challenges which may take a while to generate. Once encounter design and generation is complete, I'll move onto scene details generation based on quest, npc and encounter information. After that I'll move onto reward generation.

Combat encounter generation was tricky and took a few tries to get right. Initially I wanted to have the LLM spend experience points against a budget, selecting from enemies on a list, but I could not get a local LLM to reliably pick enemies that were within the budget and not over, under or the same level as the party. Further, there are just so many creature options for enemies, that I was using up the token limit just sending a list of over 400 options for enemies just at level 1. So I cheated. First I narrow down the enemies to those that fit the experience point budget of the encounter, then I further narrow it down by limiting the options those enemies with experience point costs/values that I can cleanly divide the budget by. Then I randomly sample 50 of those creatures and send it to the LLM and ask it to select a single creature that makes sense in the context of the scene. I then multiply the number of creatures to meet the budget of the encounter. This way if the LLM thinks a skeleton guard (20xp) makes the most sense for the encounter (80xp budget), it'll add 4 skeleton guards to the enemy list. This way the LLM can focus on picking a single creature that makes sense for the scene rather than trying to balance the encounter on it's own. It results in combat encounters that aren't very creative, but it's reliably balanced instead of spamming a bunch of unrelated creatures.

I've added example quest data to the `output` directory to show what the quest data actually looks like at this stage of development.
