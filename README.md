# Agentic Pathfinder 2e Module Generator (Working Name)
This will house the development of the Pathfinder 2e Module Generator.

## The Goal
To create and develop an adventure module generator for Pathfinder 2e.

### What is an Adventure Module?
An adventure module consists of a quest, which is a story with three acts. Each act has a number of scenes, and each scene has an encounter. The adventure module also includes a number of NPCs and locations, as well as treasure. These are all generated by the system. A module should be balanced for a party of 4 level 1 characters (number of characters and level will be adjustable) and the sum of all encounters should have an experience total of 1000 or more which is the amount needed to gain a single level. An adventure module should be able to be played over the course of 2 to 3 3-hour sessions.

#### Why does every scene have an encounter, and why only one?
LLMs are dumb. They are not capable of reliably creating the logic chains required to produce multiple encounters per scene let alone how to write a scene that's purely for character interaction. The easiest way I could approach the problem of roleplay scenes was to treat them as social encounters where the players attempt to influence one or more NPCs. This way the adventure module will still feel like a published adventure as it's played. And limiting the number of encounters to one per scene keeps things simple for an otherwise incredibly complex task.

#### Any other limitations?
Yes, many. For one thing, the quest in the adventure module is basically a railroad (or rollercoaster if you want to have fun), so players are expected to move from scene to scene in order, leaving very little room for them to go off an explore or investigate on their own. Additionally, this means that adventure modules produced by this generator are going to be, at a meta level, extremely similar, even if the details might be interesting or unique. I would not produce 20 modules at progressive levels, call it an adventure path, and expect players to not notice the patterns.

Players also don't really get any choices to influence the quest. There is sometimes an illusion of choice generated by the LLMs as they try to make the modules feel more interactive, but the quest is largely linear and set in stone from the start. Think of it less like a choose your own adventure book and more like a regular book where the players get to roll some dice at certain points and the story is over if they fail too badly.

Encounters are roughly balanced (very roughly), and the number of encounters and their suggested rewards consistently exceeds the 1000xp threshold and reward budget by about 15 to 25% on average. Restricting prompts to lower limits results in multiple extreme encounters, so for now, it's less of a problem and more of a feature that the modules have a bit of extra padding in terms of rewards. Plus, it's more about the fun playing the game, and more lower-threat encounters is better than the alternative.

### Why an LLM-Based Generator?
Gamemasters have always had access to random tables for generating game content. These days there are a plethora of random generators for encounters, loot, npcs, etcetera, that can be found online. The purpose of this tool is not to replace the GM or those other tools, but to provide a tool that can generate balanced, ready-to-play, adventure modules in an effort to get people playing at the table faster.

Using an LLM is essentially like using a fancy random number generator, but instead of integers it spits out strings of words that, fingers crossed, are coherent enough to tell a story. And that's really all this tool is going to be, a fancy random number generator that slowly strings together a bunch of other fancy number generators and outputs something that resembles an adventure module.

#### LLM Models Used
I'm currently testing using Gemma4:12b for creativity and reasoning, Gemma3:4b for simple writing and decision making, and Qwen2.5:7b for data extraction. I might try testing other models once I've finished initial development, but that's not likely to happen for a while. Note, I did create custom agents using model files to increase the token limit to 16384. These models are currently being run on a computer with 32GB of DDR4 RAM and an RTX 3060 Ti.

You could branch this module generator and modify the agents to use cloud LLMs, but that's not that goal of this project. I want to avoid using API keys or cloud based LLM providers as much as possible. Mainly because I disagree with some of the practics of cloud based LLM providers, and, to a lesser extent, the number of tokens this generator would use would probably bankrupt a small nation.

## Who should use this tool?
No one. No one should use this tool. It takes all the imagination and creativity out of creating a Pathfinder 2e adventure. If you're a new GM, go read a book. Read a module. Read a adventure path. Learn how they work. Actually put some thought into what you're doing. This tool does not help you become a better GM. If anything, it teaches you to be a lazy, uncreative GM.

If you're an experienced GM, you're better than this tool. You don't need this tool. You can make your own adventures. You can make better adventures than this tool. Don't use this tool.

### So who, actually, is this tool for?
I don't know. Maybe someone will enjoy the novelty, or some GM is dealing with burnout, but still wants to keep playing with their friends. Maybe someone calls out sick and the group still wants to play and they don't have $5 to drop on a well-written adventure created by experts on DriveThruRPG, but they do have a decent computer with at least 32GB of RAM and they're willing to spend a few hours generating the adventure.

This tool is not intended to replace homebrew content, nor is it a replacement for published adventure modules that have gone through rigorous review and testing by some of the most creative minds out there. It's going to have balancing, continuity and logic issues. What will be produced by this tool will in no way be a finished product. My best hope for this project is that it will help people better learn and understand Pathfinder 2e and gamemastering while providing another asset in a GM's toolkit for having fun with their friends.

### If no one should use it, why are you building it?
I'm a career programmer, and the AI genie is out of the bottle and it's never going back in. I wanted to learn how to incorporate AI agents into software so I can better explain why it's usually a bad idea to do so. LLMs are not true virtual intelligences, at best they're a simulation of a conversation. They don't actually think and have no consciousness or awareness. They're just incredibly sophisticated autocomplete systems that have been trained on the works of real intelligence, humans. As a programmer, I need to know how they work, how they integrate with applications and how best to utilize them. This project is just a way of making that learning fun by combining it with my TTRPG hobby. And by providing this project on GitHub, I'm hoping that those that think of using it learn a bit about LLMs and their limitations along the way.

### Can I sell modules generated by this tool?
Don't. Just... don't. Ok? You're better than that. Be better. Besides, by using Paizo content, the modules produced by this generator fall under the Open RPG Creative (ORC) License as derivative works. And as far as I know, as I am not a lawyer, Paizo doesn't like generative AI produced content.

## Current Progress
The quest generator can now produce a full Quest in JSON format using Pydantic AI in about 90 minutes (which I am working on reducing). This includes 3 acts, 5 to 9 scenes per act, 1 encounter per scene (either combat, social, skill challenge or hazard) with enemies, hazards, obstacles or NPCs where applicable. It also generates treasure for each encounter and has full narrative introductions and resolutions for each scene and encounter.

I had to cheat encounter creation in a lot of ways to get it working. Combat encounters are limited to a single creature type, multiplied based on encounter difficulty. For example, the party might face four goblins or two skeletons or a single ogre. Hazards are just pulled from the full list of pregenerated hazards, but I am considering developing a hazard generator. Skill Challenges are a bastardization of the victory point subsystem and simplify a lot of the rules just to get something playable. Similarly, social encounters are just an extremely simplified version of the Influence subsystem.

Similarly, reward generation is cheated by letting an LLM select a single item from a random selection of items that makes sense for an encounter and then providing the rest of the reward in currency.

I still need to expand the NPC naming tools to account for the six or so ancestries that have more structured naming conventions, but pulling randomly from a list of names will do for now.

I also need to break up the npc concepts so a single agent doesn't generate the scene roles with the quest role. I'm running into issues where the scene roles are incomplete during extraction and breaking it up so Gemma4 generates the NPC quest role and Gemma3 generates each scene role should both speed up NPC generation and prevent incomplete scene roles.

I'm currently working on writing the code to turn that JSON data into a markdown adventure module. This markdown file will be considered a "rough draft" and converted to HTML which I'm hoping to be able to hand off to a Microsoft AutoGen agent group to clean up, edit, review, and format into a "final draft" document that can be opened on any device or simply printed off. The final output will include instructions on how to run the adventure as a gamemaster with clearly labeled narrative text to be read to the players, encounter details, and links to Archives of Nethys for specific rules such as subsystems and stat blocks for creatures and hazards.

Next I'll need to figure out user interaction and how I want to let users input party size and level, and whether or not I want to allow the player to define part of the quest concept, like theme, setting or even the plot hook. I'm leaning towards using CustomTkinter with its more modern design to create a GUI for inputing those details. Plus, I think I'd eventually like to expand this module generator into a multipurpose generator in the future to generate individual components of the quest like an NPC generator or an encounter generator. So imagine a dashboard that lets you input specific details and you can then generate a single NPC, a random encounter, or an entire module at the push of a button.

I've given some thought to map generation, but I don't think local LLMs are just there yet, and besides, I think I'm drawing the line at generative art. I think it's one thing to use an LLM to create a random plot hook and then expand that into a full adventure module, which is really just a series of iterative randomizations. It's another thing to take away from the player's imagination by using AI to define how the scenes and encounters actually look. I don't want to take away from player creativity even if, by definition, any module produced by this generator takes away much of their agency. (It takes away so much agency, choo choo!)

I've added example quest data to the `output` directory to show what the quest data actually looks like.

## Usage and Installation

### Clone the Repository
1. Clone the repository using `git clone https://github.com/Wyrdsmith/instantpathfinder.git`

### Set up Ollama
1. Install and set up Ollama to serve local LLMs. Follow the instructions on the [Ollama website](https://ollama.com/).
2. Pull gemma4:12b, gemma3:4b and qwen2.5:7b using `ollama pull <model_name>`
3. Create custom gemma4-quest, gemma3-quest and qwen2.5-quest using the model files in the `agent_files` directory. Use command `ollama create <model_name> -f <path_to_modelfile>`

### Run Quest Generator
1. Navigate to the root `instantpathfinder` directory
2. Run `python module_generator.py`

### Database Instantiation
The database should already work as is, but you can use `utilities/db_manager.py` to create and populate a new database file if needed. 

Run `python -i utilities/db_manager.py` to interact with the database and make changes to the datasets.
